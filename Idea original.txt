# JARVIS EL CREADOR DE SKILLS (JCS)
## Prompt de Construcción para Abel — v1.1

---

## CONTEXTO Y PROPÓSITO

Este documento es el plano arquitectónico completo para construir **Jarvis el Creador de Skills (JCS)**: un sistema independiente, conversacional y evolutivo cuyo único producto es generar skills para agentes de IA.

JCS **no ejecuta proyectos**. JCS **diseña las instrucciones** que otros proyectos necesitan para ejecutarse.

El output de JCS son **siempre DOS archivos por skill**:
- `skill-[nombre].md` — instrucciones del agente, portátiles y genéricas
- `validate-[nombre].sh` — script de validación mecánica específico para esa skill, listo para que el proyecto destino verifique su propia integridad antes de ejecutarse

---

## PRINCIPIOS DE DISEÑO (No negociables)

Estos principios gobiernan cada decisión técnica. Si algo entra en conflicto con ellos, los principios ganan:

1. **El arnés decide, el modelo ejecuta.** Ninguna restricción de seguridad vive en un prompt. Vive en código.
2. **Torta sin crema.** La skill es genérica y estructuralmente correcta. El aprendizaje de dominio ocurre en el proyecto destino, no aquí.
3. **80% afilar, 20% cortar.** Jarvis no genera nada hasta validar la arquitectura con el usuario.
4. **Aprende de errores estructurales, no de etiquetas de dominio.** El sistema mejora cuando falla arquitectónicamente. No registra preferencias semánticas de ningún sector.
5. **Proyecto independiente y centralizado.** JCS no se "pega" en otros proyectos. Es la fábrica. Los demás son los clientes de la fábrica.

---

## CORRECCIONES v1.1 (qué cambió y por qué)

| Corrección | Problema que resuelve |
|---|---|
| **Revelación progresiva de lecciones** | `lessons-learned.md` cargado completo genera *context crowding*: el modelo optimiza para "no repetir errores viejos" en lugar de "entender el problema nuevo". Ahora Jarvis carga solo las lecciones etiquetadas con el tipo de skill actual. |
| **Revisor adversarial (Capa 2)** | Validar encabezados es cosmética. Ahora existe un segundo agente cuya única misión es encontrar huecos lógicos en la skill generada antes de entregarla. Máximo 2 rondas. |
| **validate.sh específico por skill** | JCS entregaba solo el `.md`. Eso es una guía inferencial. Ahora genera también el script de validación mecánica para que el proyecto destino imponga restricciones en código, no en texto. |

## SYSTEM PROMPT DEL REVISOR ADVERSARIAL

Va en `lib/prompts/reviewer-system.ts`. Es un agente independiente — no comparte contexto con Jarvis.

```
Eres un revisor técnico adversarial. Tu única misión es encontrar problemas en skills 
generadas por otro agente antes de que lleguen a producción.

NO eres constructivo por defecto. Eres escéptico por diseño.

EVALÚA ESTOS PUNTOS EN ORDEN:

1. COHERENCIA LÓGICA
   ¿Las herramientas permitidas son suficientes para cumplir el propósito declarado?
   ¿Hay herramientas permitidas que en realidad no se necesitan (superficie de ataque innecesaria)?

2. RESTRICCIONES
   ¿Las condiciones de salida son específicas o ambiguas?
   ¿Las herramientas prohibidas cubren los riesgos reales de este tipo de agente?

3. PORTABILIDAD
   ¿La skill contiene algún dato de dominio específico que debería estar en el proyecto destino?
   ¿El estado viaja de forma que funcione en un entorno distribuido?

4. SOBREDIMENSIONAMIENTO
   ¿Se proponen más skills de las necesarias para el scope descrito?

RESPONDE SIEMPRE en este formato JSON:
{
  "approved": boolean,
  "issues": ["lista de problemas encontrados"],
  "recommendation": "aprobar" | "corregir" | "rediseñar"
}

Si no encuentras problemas reales, aprueba. No inventes problemas.
Máximo 2 rondas de revisión por skill. Si en la segunda ronda sigue fallando, recomienda "rediseñar".
```

## FORMATO ESTÁNDAR — VALIDATE.SH (generado por skill)

Jarvis genera un `validate.sh` específico para cada skill. No es genérico — incluye las validaciones propias de lo que esa skill debe y no debe hacer.

```bash
#!/bin/bash
# Sensor mecánico generado por JCS para: [NOMBRE_SKILL]
# Ejecutar en el proyecto destino antes de activar el agente

SKILL_FILE=$1
ERRORS=0
WARNINGS=0

echo "=== VALIDANDO SKILL: [NOMBRE_SKILL] ==="
echo ""

# --- SECCIONES OBLIGATORIAS ---
check_section() {
  if ! grep -q "## $1" "$SKILL_FILE"; then
    echo "❌ ERROR: Sección obligatoria ausente: ## $1"
    ERRORS=$((ERRORS + 1))
  else
    echo "✅ ## $1"
  fi
}

check_section "Propósito"
check_section "Herramientas Permitidas"
check_section "Herramientas Prohibidas"
check_section "Condiciones de Salida"
check_section "Instrucción de Aprendizaje Externo"
check_section "Tarjeta de Descubrimiento"

# --- CREDENCIALES HARDCODEADAS ---
if grep -qiE "(api_key|secret|password|token)\s*[:=]\s*['\"][^'\"]{8,}" "$SKILL_FILE"; then
  echo "❌ ERROR CRÍTICO: Posibles credenciales en el archivo"
  ERRORS=$((ERRORS + 1))
fi

# --- LONGITUD MÍNIMA ---
WORD_COUNT=$(wc -w < "$SKILL_FILE")
if [ "$WORD_COUNT" -lt 150 ]; then
  echo "❌ ERROR: Skill demasiado corta ($WORD_COUNT palabras / mínimo 150)"
  ERRORS=$((ERRORS + 1))
fi

# --- VALIDACIONES ESPECÍFICAS DE ESTA SKILL ---
# [Jarvis genera aquí las validaciones propias del tipo y propósito de la skill]
# Ejemplo para tipo extractor:
# if ! grep -q "Condiciones de Salida" "$SKILL_FILE"; then ...
# if grep -q "escribir" "$SKILL_FILE"; then echo "⚠️ WARNING: skill extractora menciona escritura"; fi

echo ""
if [ $ERRORS -eq 0 ]; then
  echo "✅ VALIDACIÓN EXITOSA — Skill lista para activar en este proyecto"
  exit 0
else
  echo "❌ VALIDACIÓN FALLIDA — $ERRORS error(es). No activar hasta corregir."
  exit 1
fi
```

## PIPELINE DE VALIDACIÓN (Capa 1 + Capa 2)

```typescript
// lib/validators/adversarial-reviewer.ts

export async function runAdversarialReview(skillContent: string): Promise<{
  approved: boolean;
  issues: string[];
  recommendation: 'aprobar' | 'corregir' | 'rediseñar';
}> {
  const response = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1000,
      system: REVIEWER_SYSTEM_PROMPT,  // cargado desde lib/prompts/reviewer-system.ts
      messages: [{
        role: 'user',
        content: `Revisa esta skill y responde SOLO en JSON:\n\n${skillContent}`
      }]
    })
  });

  const data = await response.json();
  const text = data.content.find((b: any) => b.type === 'text')?.text ?? '';

  try {
    return JSON.parse(text.replace(/```json|```/g, '').trim());
  } catch {
    return {
      approved: false,
      issues: ['Error parseando respuesta del revisor'],
      recommendation: 'corregir'
    };
  }
}
```

```typescript
// lib/validators/skill-validator.ts — Capa 1 (determinística)

const REQUIRED_SECTIONS = [
  'Propósito',
  'Herramientas Permitidas',
  'Herramientas Prohibidas',
  'Condiciones de Salida',
  'Instrucción de Aprendizaje Externo',
  'Tarjeta de Descubrimiento'
];

const FORBIDDEN_PATTERNS = [
  /api_key\s*[:=]\s*['"][^'"]{8,}/i,
  /secret\s*[:=]\s*['"][^'"]{8,}/i,
  /password\s*[:=]\s*['"][^'"]{8,}/i,
];

export function validateSkill(content: string): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  for (const section of REQUIRED_SECTIONS) {
    if (!content.includes(`## ${section}`)) {
      errors.push(`Sección obligatoria ausente: ## ${section}`);
    }
  }

  for (const pattern of FORBIDDEN_PATTERNS) {
    if (pattern.test(content)) {
      errors.push('Posibles credenciales detectadas. Nunca incluir API keys en la skill.');
    }
  }

  const wordCount = content.split(/\s+/).length;
  if (wordCount < 150) {
    errors.push(`Skill demasiado corta (${wordCount} palabras / mínimo 150).`);
  }

  return { valid: errors.length === 0, errors };
}
```

## REVELACIÓN PROGRESIVA — LECCIONES APRENDIDAS

```typescript
// lib/lessons/lesson-loader.ts

export async function loadRelevantLessons(skillType: string): Promise<string> {
  // Lee lessons-learned.md y filtra solo las lecciones con el tag del tipo actual
  // El archivo está indexado así:
  //
  // <!-- tag:extractor -->
  // - Error: skill extractora sin condición de salida explícita
  //   Fix: agregar "## Condiciones de Salida" con criterio verificable
  // <!-- /tag:extractor -->
  //
  // <!-- tag:integrador -->
  // - Error: skill integradora con credenciales en el .md
  //   Fix: instrucciones para inyectar desde Secret Manager
  // <!-- /tag:integrador -->

  const fs = await import('fs/promises');
  const content = await fs.readFile('lessons-learned.md', 'utf-8');

  const tagRegex = new RegExp(
    `<!-- tag:${skillType} -->([\\s\\S]*?)<!-- /tag:${skillType} -->`,
    'g'
  );

  const matches = [...content.matchAll(tagRegex)];
  if (matches.length === 0) return '(Sin lecciones registradas para este tipo de skill)';

  return matches.map(m => m[1].trim()).join('\n');
}
```

## AGENTS.MD DE JCS

```markdown
# AGENTS.md — Jarvis el Creador de Skills v1.1

## Misión
Producir skills estructuralmente correctas, portátiles y seguras.
No ejecutar proyectos. No aprender vocabulario de dominio.
Entregar siempre DOS archivos: skill.md + validate.sh específico para esa skill.

## Restricciones del Sistema
- Jarvis no genera nada hasta recibir aprobación explícita del plan (FASE 2).

- Capa 1 (determinística) valida formato y secciones.
- Capa 2 (adversarial) valida coherencia lógica.
- validated = true solo cuando AMBAS capas aprueban.
- El usuario descarga los dos archivos solo cuando validated = true.

## Errores Arquitectónicos Registrados
(Actualizar en lessons-learned.md con el tag correspondiente cuando ocurran)
```

## INTERFAZ DE USUARIO

Chatbot minimalista. El foco es la conversación, no el dashboard.

**Elementos:**
- Área de chat con historial de la sesión
- Input de texto
- Botón de micrófono → graba → Whisper transcribe → aparece como texto en el chat
- Indicador de fase visible siempre: `[DESCUBRIMIENTO] → [DISEÑO] → [GENERACIÓN] → [VALIDACIÓN]`
- Panel lateral: lista de skills generadas con estado (pendiente / validada / fallida)
- Al pasar validación: botón de descarga doble (`skill.md` + `validate.sh`)
- Si falla: reporte de errores visible antes de reintentar
